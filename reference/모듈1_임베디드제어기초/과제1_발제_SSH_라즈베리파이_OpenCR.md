# 모듈 1 과제 1 발제 — 원격 환경 구성과 모터 응답 확인

## 과제 목적

SSH 원격 환경에서 OpenCR에 펌웨어를 업로드하고, 다이나믹셀에 목표값을 전달한 뒤 측정 기록을 근거로 실제 응답을 설명합니다. 연결 강의는 1강과 5강입니다.

## 수행 환경과 필수 조건

- 라즈베리파이 OS: **Ubuntu Server 22.04**.
- 제어기: **OpenCR 1.0**. 모터: **다이나믹셀 1개**.
- PC는 라즈베리파이에 **SSH로 접속하는 용도**로만 사용합니다.
- OpenCR은 라즈베리파이에 USB로 연결해야 합니다.
- **펌웨어 업로드는 반드시 라즈베리파이에서 수행**해야 합니다.
- **시리얼 명령 송신, 측정값 수신과 로그 저장도 라즈베리파이에서 수행**해야 합니다.
- PC에서 직접 업로드하거나 PC의 시리얼 모니터를 사용하는 방식, GUI 원격 데스크톱은 인정하지 않습니다.
- 제공 펌웨어를 사용할 수 있습니다. 펌웨어 자체의 컴파일은 필수 요구사항이 아닙니다.

## 요구사항

### 1. 원격 수행 환경 구성

라즈베리파이의 OS, SSH 접속, OpenCR USB 인식과 포트 접근 권한을 확인하세요. 본인이 작업한 장치와 사용한 포트를 기록하세요.

### 2. OpenCR 펌웨어 업로드

라즈베리파이에서 제공 펌웨어를 OpenCR에 업로드하세요. 업로드 성공을 확인할 수 있는 출력과 업로드 이후 장치가 정상적으로 준비되었음을 보여 주는 기록을 남기세요. 파일 체크섬만 일치하는 것은 업로드 성공 증거가 아닙니다.

### 3. 목표 입력과 응답 기록

과제용으로 검증된 작은 상대 목표각과 낮은 속도 상한을 사용하여 한 번 실행하세요. 목표 변경 이후의 측정 기록을 5행 이상 확보하고, 종료 시 정지 여부를 확인하세요. 이번 과제에서는 게인 비교나 반복 튜닝을 요구하지 않습니다.

### 4. 결과 설명

사용한 모터 모델·ID, 게인, 목표각, 속도 상한과 예제 이름을 적으세요. 기록에서 목표값·측정값·제어 출력을 구분하고 각각의 단위를 쓰세요. 목표에 가까워졌는지 실제 움직임과 기록을 근거로 2문장 이내로 설명하세요.

## 제공 자료와 적용 조건

- [OpenCR 빌드·업로드 가이드](OpenCR_빌드_업로드_가이드.md): 라즈베리파이에서 직접 빌드하는 경우 참고하세요. 제공 펌웨어 사용도 가능하며 직접 컴파일은 필수 평가 항목이 아닙니다.

- [과제용 P 제어 소스](examples/opencr_position_p/opencr_position_p.ino)
- [펌웨어 및 적용 장비 정보](firmware/README.md)

제공 바이너리는 XM430-W350(모델 1020), ID 12, 1 Mbps, Protocol 2.0 기준입니다. 다른 장비는 해당 모델·설정에 맞춰 검증된 호환 자료를 사용해야 합니다. 모델 검사를 우회하지 않습니다. OpenCR 공식 보드 매니저의 ARM SBC 제한을 고려하여 사전 빌드 펌웨어 사용을 허용합니다.

제공 자료의 장비별 동작 검증 여부를 확인하세요. 수강생은 모터 고정, 이동 범위 확보, 정지 방법과 전원 차단 위치를 확인한 뒤 수행하세요. SSH 종료를 모터 정지로 간주하지 않습니다.

## 제출물

SpartaPA 조직의 **`physicalai-lv2-이름`** 저장소에 `lv2_module1/` 폴더를 만들고 제출하세요. 결과 설명은 **`lv2_module1/report.md`의 `## 문제 1`**에 작성합니다. 설명은 A4 약 1쪽 분량을 권장하며 Markdown 형식을 유지합니다. 기한과 제출 경로는 운영 공지에 따릅니다.

| 저장 경로 | 용도 |
|---|---|
| README.md | 수강생 이름과 모듈별 폴더 링크 |
| lv2_module1/README.md | 장비·환경·실행 방법과 결과 파일 위치 |
| lv2_module1/report.md | 문제별 설정·증거·해석. 오늘은 문제 1 작성 |
| lv2_module1/results/ | 환경 확인, 업로드, 실행 A 기록 |

이후 문제 2~4는 같은 `report.md`에 이어 쓰고, 모듈 2 이후는 같은 저장소에 `lv2_module2/` 등의 폴더를 추가하세요.

| 제출물 | 포함할 내용 |
|---|---|
| lv2_module1/report.md | 장비·환경·설정, 값의 이름과 단위, 결과 설명 |
| lv2_module1/results/환경확인.txt 또는 화면 캡처 | 라즈베리파이 호스트명, Ubuntu 버전, 아키텍처, 사용 포트 |
| lv2_module1/results/upload.log 또는 화면 캡처 | 라즈베리파이에서 수행한 업로드와 성공 확인 |
| lv2_module1/results/실행A.log 또는 화면 캡처 | 목표 변경 이후 측정값 5행 이상과 정지 확인 |

오늘 작성한 내용을 커밋·푸시하고 해당 커밋 또는 `report.md` URL을 제출하세요. 모듈 1의 모든 문제를 마친 뒤 최종 제출 태그 `lv2-module1-submit`을 붙입니다. 자세한 공통 기준은 [과제 안내](../과제_안내.md)를 따릅니다.

비밀번호·개인 키 등 인증 정보는 제출하지 않습니다. 이후 문제 2·3에 같은 실행 A 기록을 재사용할 수 있습니다.

## 평가 기준 — 25점

| 평가 항목 | 배점 | 확인 내용 |
|---|---|---|
| 설정과 실행 | 10점 | 지정 환경과 SSH 조건 준수, 라즈베리파이에서 업로드·시리얼 수신, 설정 기록과 정지 확인 |
| 목표·측정·출력 구분 | 10점 | 본인 기록에 근거한 값의 구분과 올바른 단위 |
| 관찰 설명 | 5점 | 실제 기록과 일치하는 응답 설명 |

목표에 완벽히 도달해야만 평가받는 과제가 아닙니다. 설정·측정·해석의 일치 여부를 확인합니다. 장비 문제로 제공 로그를 사용한 경우에는 대체 자료임을 표시해야 하며, 수행하지 않은 업로드나 장비 구동을 완료했다고 기록하면 안 됩니다.

오늘 제출 범위는 문제 1까지입니다. 문제 2~4, 실행 B, 새 PID 구현, micro-ROS 설치는 오늘 요구사항에 포함하지 않습니다.
