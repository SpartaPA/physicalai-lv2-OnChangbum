# Lv.2 과제 발제 문서

수강생이 과제의 목적, 수행 조건, 요구사항, 제출물과 평가 기준을 확인하는 문서입니다.

기준은 [Lv.2 커리큘럼 개요](00_커리큘럼_개요.md)와 [Lv2.xlsx](Lv2.xlsx)입니다. 강 번호·시수·성취도 연결은 `Lv2_시수정리`와 `Lv2_강의계획`, 단계별 채점 기준은 실제 시트명 `시트2`의 Lv.2 성취도 블록을 따릅니다. 아래 문항별 **4점·5점 기준은 해당 엑셀 원문**이며, 제출 증거와 파일 구성은 그 기준을 확인하기 위한 안내입니다.

---

**모듈 1 개정 안내:** OpenCR·다이나믹셀 통합 4문제·각 25점(총 100점)을 적용합니다. 기존 1~5점 성취도 기준과 자동 환산하지 않습니다.

제출 저장소·폴더 구조·최종 제출 태그는 [과제 안내](과제_안내.md#제출-저장소와-폴더-구조)를 따릅니다. 모듈 완료 태그는 `lv2-module{번호}-submit`이며, 오늘 문제 1 중간 제출에는 전체 완료 태그를 붙이지 않습니다.

## 1. 발제 개요 — Lv.2 과제는 세 축입니다

| 축 | 무엇인가요? | 언제 진행하고 제출하나요? | 평가 기준 |
|---|---|---|---|
| 미니 퀴즈 | 각 강의 끝 5문항, 75강 총 375문항 | 강의 직후 풀이, 모듈 종료 시 일괄 제출 | 문항당 2점, 총 750점 |
| 실습 산출물 | 강의 중 작성한 코드·노트북·설정·실험 결과 | 해당 실습 시간에 작성, 모듈 종료 시 일괄 제출 | 모듈당 100점 |

> **오늘의 필수 이해 기준**: 무엇을 구현할지, 어떤 증거를 제출할지, 4점과 5점의 차이를 설명할 수 있으면 과제를 시작할 준비가 된 것입니다. 모든 심화 항목을 한 번에 구현하려고 하지 마세요.

## 2. 공통 진행 방식과 제출 규칙

### 진행 방식

1. 해당 모듈의 실습을 실행해 기준 결과를 확보합니다. 이후 과제 문제 순서대로 구현합니다.
2. 각 문제의 **필수 수행(4점)**을 먼저 완성하고, 같은 조건에서 다시 실행해 결과를 확인합니다.
3. 코드만 제출하지 않고 **입력·설정 → 실행 → 결과 → 해석**을 함께 남깁니다. 실패했다면 실제 실패 로그와 원인 가설을 기록합니다.
4. 필수를 완료한 뒤 해당 문항의 **심화(5점)**를 진행합니다. 단순히 기능을 추가하거나 보고서를 길게 쓰는 것으로 대체할 수 없습니다.
5. 마지막으로 새 터미널 또는 초기화한 노트북에서 재현하고, 제출 파일을 점검합니다.

현재 저장소의 강의 코드·실습 결과를 출발점으로 사용합니다. **별도의 Lv.2 과제 템플릿·자동 채점기가 배포되었다고 전제하지 않습니다.** 아래 파일 트리는 수강생이 정리할 제출 구조이며, 아직 제공되지 않은 노트북이나 데이터의 다운로드를 요구하는 안내가 아닙니다.

### 공통 제출 규칙

- SpartaPA 조직의 **`physicalai-lv2-이름`** 저장소 하나에 모든 과제를 누적합니다. 개인·팀 과제 모두 해당 저장소의 `lv2_module{번호}/` 폴더에 제출합니다. 팀 과제는 공통 결과와 본인의 기여를 기록합니다.
- 각 모듈 폴더에 `README.md`와 **`report.md`**를 포함합니다. `README.md`에는 환경·설치·실행·입력 데이터 위치를, `report.md`에는 `## 문제 1`부터 문항 순서대로 검증·해석을 작성합니다.
- 터미널 출력은 **텍스트 코드 블록**으로 붙입니다. 이미지 자체가 증거인 RViz·검출 화면·그래프는 캡처로 첨부하고, 수치 평가에는 원본 CSV나 로그도 함께 냅니다.
- `build/`, `install/`, `log/` 등 재생성 가능한 빌드 폴더와 `.venv/`, `__pycache__/`는 제외합니다. 직접 수집한 **평가 로그**는 `results/`에 보존합니다.
- 노트북은 **Restart Kernel → Run All** 후 결과가 남은 상태로 저장합니다. ROS2 패키지는 새 터미널에서 환경을 준비하고 빌드·실행합니다.
- Python·ROS2 배포판·주요 라이브러리 버전, 장치·펌웨어·모델·데이터 버전을 기록합니다. 다른 장비에서 동일한 실행 파일이 그대로 동작한다고 가정하지 않습니다.
- 난수 실험은 강의에 지정된 시드를 우선 사용합니다. 별도 지정이 없으면 기본 시드 42를 사용하고, 여러 시드 비교 시 목록을 기록합니다. **시드가 같아도 GPU·시뮬레이터·실기 결과가 완전히 같지는 않으므로**, 수치 차이의 원인과 조건을 함께 설명합니다.
- 큰 데이터·bag·체크포인트는 허용된 저장 위치에 두고 접근 가능한 링크, 파일 크기·해시, 사용한 구간을 `README.md`에 기록할 수 있습니다. 링크를 쓴 경우 채점자가 열 수 있는지 확인합니다. 저장소 공개 전환은 제출 조건이 아닙니다.
- 외부 코드·모델·데이터·AI 도구를 사용한 경우 출처, 사용 범위, 직접 수정·검증한 부분을 구분합니다. 본인이 설명할 수 없는 실행 결과를 제출하지 않습니다.

### 비교 실험의 공통 규칙

**한 번에 바꿀 조건과 고정할 조건을 먼저 적습니다.** 제어기는 목표값·부하·샘플링 주기를, 비전은 영상·해상도·카메라 보정을, 학습은 데이터 분할·시드·평가 에피소드를, 주행은 지도·시작점·목표·장애물 조건을 맞춥니다.

성공률에는 성공 횟수와 전체 시도 횟수를, 지연에는 측정 구간·단위·표본 수를 함께 기록합니다. 정확도·오차·정착시간·충돌 등은 계산 정의와 판정 기준을 명시합니다. 기준을 결과를 본 뒤 유리하게 바꾸지 않습니다. 강의나 루브릭에 없는 공통 FPS·오차 합격선을 임의로 적용하지 않습니다.

### 팀 과제 추가 제출물 — ⑤·⑩

- `team.md`: 역할 분담표, 개인별 구현·검증 항목, 커밋·리뷰 또는 이에 준하는 작업 기록.
- `presentation.md`: 시스템 구조 → 시연 → 정량 결과 → 실패·개선 → 개인 기여 순서의 발표 자료.
- 팀 결과물을 함께 제출하되, 각자 담당한 코드와 판단 근거를 설명할 수 있어야 합니다. 개인별 평가 반영 방식은 운영 공지에 따릅니다.

## 3. 과제 ① — OpenCR·다이나믹셀 통합 과제 (축소 개정)

**범위:** 이론 1~4강 + 실습 5~8강 / 개인 4문제 / 예상 90분 / 100점.

**이 모듈은 위 공통 제출 규칙보다 아래 개정본을 우선 적용합니다.** 기존 성취도 엑셀의 구현 4점·5점 기준과는 다른 축소 평가입니다.

1. 명령과 움직임 확인: 1강 + 5강, 25점.
2. 센서값과 피드백 해석: 2강 + 6강, 25점.
3. P 게인 하나만 바꿔 두 번 비교: 3강 + 7강, 25점.
4. 제어 주기와 통신 흐름 해석: 4강 + 8강, 25점.

OpenCR과 다이나믹셀 1개 및 검증된 수업 예제를 사용합니다. 보고서 2쪽 이내와 실행 로그 2개로 제출합니다. ADC·외부 엔코더 배선, 새 PID 구현, micro-ROS 신규 구축은 요구하지 않습니다. 문제 4는 제공 기록 해석으로 수행하며 네트워크 구현 성취를 인증하지 않습니다.

자세한 문제와 채점 기준: [모듈 1 과제 발제 개정본](모듈1_임베디드제어기초/과제_발제_OpenCR_다이나믹셀_4문제.md).

## 4. 과제 ② — 로봇팔 기구학·궤적·제어 검증

**범위:** 모듈 ②, 9~15강·27h / **개인 4문제** / 성취도 17~20.

### 과제 목적

> “로봇팔이 목표 위치에 도착하려면 좌표 계산과 움직임 계획이 함께 맞아야 합니다. 같은 팔 모델을 사용해 말단 위치와 속도를 계산하고, 부드러운 궤적을 만든 뒤 제어 성능을 비교해 봅시다. 모듈 ①에서 배운 PID와 Lv.1 좌표 변환을 다시 사용합니다.”

### 어떤 작업을 하나요?

| 문제·성취도 | 필수 수행 — 4점 기준 | 심화 — 5점 기준 | 제출 증거 |
|---|---|---|---|
| **1. 2~3DOF 순기구학**<br>성취도 17 · 13강 | FK를 동차변환 체인으로 구현하고 엔드이펙터 위치가 기대값과 일치 | 4점을 충족하고 여러 조인트 각에 대해 위치를 검증함 | 팔 모델·좌표계·동차변환 체인, 관절값별 말단 위치, 독립 계산과의 검증. |
| **2. Jacobian과 특이점**<br>성취도 18 · 14강 | Jacobian 구성, 속도 변환, 특이점 탐지를 모두 충족 | 4점을 충족하고 특이점 부근 거동을 분석함 | Jacobian·속도 변환 결과와 특이점 판정 근거, 정상 자세와 특이점 근처의 비교. |
| **3. Quintic 궤적 생성**<br>성취도 19 · 15강 | 속도/가속도 제약 Quintic 궤적을 생성하고 경계 조건을 만족 | 4점을 충족하고 속도/가속도 프로파일을 시각화함 | 경계 조건·계수·시간 구간, 위치·속도·가속도 그래프와 끝점 검증. |
| **4. PID 제어 성능 비교**<br>성취도 20 · 15강 | PID를 튜닝하고 수렴/안정성을 지표로 확인 | 4점을 충족하고 게인별 응답을 비교 분석함 | 동일 목표·모델에서의 게인별 응답, 오버슈트·정착시간 등 지표와 선택 근거. |

### 최종 제출 포맷

```text
lv2_module2/
├── README.md
├── report.md             # 문제 1~4, 팔 모델·좌표계·검증 조건
├── notebooks/            # FK·Jacobian·궤적·제어 실험
├── src/                  # 재사용한 기구학·궤적·제어 함수
├── config/               # 링크 길이·관절 범위·게인·실험 설정
└── results/              # 비교 수치·그래프·검증 결과
```

### 진행·발제 주의사항

- **15강의 궤적 생성과 PID 튜닝은 별도 성취도이므로 문제 3·4로 나눕니다.** 한 강의를 한 문제로만 세지 않습니다.
- 링크 길이와 좌표계 방향을 먼저 고정하고, 각도는 rad·deg를 구분합니다. 같은 모델을 문제 1~4에서 이어 씁니다.
- Jacobian의 특이점에서는 역행렬 계산이 실패하거나 큰 관절 속도가 나올 수 있습니다. 정상 자세와 특이점 근처의 결과를 구분해 설명합니다.
- 궤적 생성 성공과 실제 추종 성공은 별개입니다. 계획한 위치·속도·가속도와 제어기 출력·추종 오차를 나누어 제시합니다.

### 진행·발제 주의사항

- 모듈 ⑥의 지도·Nav2·계측 결과를 재사용하고, 모듈 ④의 인지 결과를 결합합니다. 변경한 부분과 기존 부분을 구분해 기록합니다.
- 미션 성공·시간초과·충돌·재계획 횟수의 정의를 먼저 합의합니다. 같은 경로 메시지가 다시 발행된 횟수를 무조건 재계획 횟수로 세지 않습니다.
- 라이다·비전 융합에는 좌표계·시간 정합·센서 누락 시 처리 방식을 포함합니다. 두 센서의 화면을 나란히 보여주는 것만으로 융합을 검증하지 않습니다.
- 조도와 장애물 배치 등 조건을 구분한 시나리오 표를 작성합니다. 회차별 결과에 성공·실패를 모두 남깁니다.
- rosbag은 기록된 입력을 다시 제공하지만 실제 물리 환경의 폐루프 주행을 그대로 재현하지는 않습니다. **오프라인 회귀 검증과 실기 주행 평가**를 구분하고, 재생 시 시계·TF·노드 중복 발행을 확인합니다.

## 14. 평가 안내와 발제 진행 순서

**모듈 1 개정 예외:** 모듈 1은 통합 4문제·각 25점(총 100점)으로 평가합니다. 아래의 기존 성취도 루브릭 안내는 나머지 모듈에 적용하며, 모듈 1 점수를 기존 1~5점 성취도 달성 점수로 자동 환산하지 않습니다.

### 평가 안내

- 모듈 과제는 **구현 성취도 45항목을 각각 1~5점으로 평가**합니다. 이론 성취도 43항목을 별도 구현 문제로 추가하지 않습니다.
- 문항별 4점·5점 조건은 위 표를 따릅니다. **1~3점도 엑셀의 해당 문항 원문 기준으로 판단**합니다. 모든 문항을 동일한 ‘몇 개 누락’ 규칙으로 일괄 환산하지 않습니다.
- 미니 퀴즈 750점, 실습 산출물 모듈당 100점, 성취도 루브릭 점수는 서로 다른 평가 축입니다. 최종 성적 반영 비율·합격 기준·지각·재제출 정책은 운영 공지에 따릅니다.
- 실행 성공과 설명 충실도는 제출 증거로 함께 확인합니다. 자동 채점기나 미공개 합격 임계값이 존재한다고 안내하지 않습니다.
